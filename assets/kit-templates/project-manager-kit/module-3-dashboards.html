Building a PM Status Dashboard with Copilot

Turn the same Planner plan into a live status view — so the steering committee gets a link instead of another email.

Where we are in the story: The steering committee wants a live view of {{PROJECT_NAME}}, not another status email. Time to build a dashboard {{PERSONA_FIRST}} doesn't have to update by hand.

What you'll learn

  • Turn existing plan data into a live status view without a data analyst
  • Scope dashboard views to the questions stakeholders actually ask
  • Choose visuals that match how a specific audience wants to see status
  • Replace a written status report with a shareable, always-current link

Lesson

Same Plan, New View

The starting point is the same Planner plan used all along. Copilot can turn that task data into a status view without needing a data analyst or a separate reporting tool.

Step 1: Ask for What the Committee Cares About

Prompt Copilot to build a view showing tasks by status, by workstream, and flagged risks — the three things a steering committee actually asks about. Not "show me everything."

In Copilot: Ask for the specific views your stakeholders ask about, by name — status breakdown, workstream progress, risk list.

Step 2: Pick the Right Visuals

Copilot proposes visuals — a status breakdown, a workstream progress bar, a risk list. {{PERSONA_FIRST}} picks the ones that match how this specific committee likes to see things, and removes the rest.

In Copilot: Swap chart types and remove irrelevant visuals until the view matches your audience's habits, not a generic dashboard template.

Step 3: Share a Link, Not a Report

The dashboard updates as the plan updates. Instead of writing a report, {{PERSONA_FIRST}} sends a link and answers questions live, in real time, instead of compiling a deck every week.

In Teams: Share the dashboard link directly in the steering committee channel instead of attaching a status document.

From Reporting to Pointing

The shift is from "build a status report every week" to "point people at a live view" — and spend the saved time on the project instead of reporting on it.

Job Aid — Quick Reference

A one-page checklist for building a PM status dashboard with Copilot.

Before You Start

  • Have your plan up to date — a dashboard is only as good as the source data
  • Know the 2-3 questions your stakeholders actually ask

Core Steps

  • Point Copilot at your plan data as the dashboard's source
  • Ask for views scoped to real stakeholder questions
  • Review and swap visuals to match audience preference
  • Share the dashboard link instead of a written report
  • Re-check the dashboard before each steering committee meeting

Common Pitfalls

  • Building a dashboard before the underlying plan data is trustworthy
  • Including every possible metric instead of the few your audience uses
  • Treating it as "set and forget" — stale bucket names confuse it

Where to Go for Help

  • Microsoft Learn documentation for Copilot in Power BI / Planner reporting
  • This kit's Prompt Library

Knowledge Check

1. What should be true before building a dashboard?

A dashboard is only as good as its source — stale or messy plan data produces a misleading dashboard.

2. What should the dashboard be built around?

Scope to real stakeholder questions, not a generic "show everything" dashboard.

3. What's the common failure mode of "set and forget" dashboards?

A live dashboard still needs a glance-check before it's trusted — plan structure drifts over time.
